# DIVINIVID Pre-Lock Exploration Program V1

## Purpose
Explore the behavior of the newly discovered DIVINIVID expression universe before final expression lock.

This program does **not** reopen the Core and does **not** resume broad visual discovery.

It takes the approved Core + B1 system and the current M1-B working anchor and tests the layers needed to turn the visual breakthrough into a usable identity system:
- typography;
- iconography/sign system;
- hero behavior;
- intensity/density;
- motion;
- digital behavior;
- application stress;
- final synthesis.

The goal is to answer how the universe behaves, not merely how it looks.

## Governing rules

### 1. Preserve the Core
No module may silently change:
- Living Darkness;
- ivory/bone evidence logic;
- Living Crimson semantics;
- aged-gold instrumentation;
- residual-ultramar discipline;
- living/ambiguous matter;
- macro/micro duality;
- dream logic + editorial authority;
- non-generic elegance;
- anti-gothic/anti-occult/anti-dark-luxury boundaries.

### 2. Preserve B1
The Route 3+4 production grammar remains the default:
- printed evidence;
- layered registration;
- erosion/transfer;
- negative shape;
- active void;
- ambiguous figure/ground.

### 3. One variable under test
Each lab changes one major system variable while everything else remains fixed.

### 4. Context minimization
Default input packet:
- Core Lock;
- B1 Lock;
- M1-B Working Anchor;
- current module contract.

Do not load the entire historical archive or 100-contract program unless a module-specific ambiguity requires it.

### 5. Human promotion only
Every output begins as `EVIDENCE_PENDING`.

No module result becomes authoritative because it is visually polished.

### 6. No downstream contamination
A rejected Typography/Iconography/Hero/Motion candidate does not become a positive reference for subsequent modules.

### 7. Quality over volume
Use the smallest number of candidates capable of distinguishing the real alternatives.

## P1 — Typography Lab

**Execution status: HUMAN APPROVED / CLOSED (2026-09-22).**

The approved visual direction is the imposing dual-editorial treatment selected by the human owner. Exact production font-family mapping is deferred to implementation and does not reopen the visual direction.

### Objective
Determine a typographic system that increases DIVINIVID identity while remaining usable across editorial, web, agency, clinical/B2B and information-heavy applications.

### Hypotheses

#### T-A — Monumental Serif Dominant
- high-authority serif display;
- restrained secondary system face;
- strongest continuity with current imagery.

#### T-B — Dual Editorial
- expressive serif for brand/display;
- severe contemporary grotesk/sans for body/system/data;
- intended balance between ritual authority and operational clarity.

#### T-C — Brutalist Inversion
- severe grotesk/sans dominant;
- serif reserved for ritual, quotation, editorial or ceremonial moments.

### Test content
All three hypotheses must be tested on equivalent:
- brand name;
- hero statement;
- body copy;
- annotation/data;
- caption;
- CTA/link.

### Acceptance
Evaluate:
- authority;
- distinctiveness;
- readability;
- macro/micro behavior;
- web viability;
- deck/document viability;
- clinical/B2B viability;
- absence of generic fashion-editorial styling.

### Budget
- 3 hypotheses in one comparative artifact;
- maximum 1 challenger only if the human gate finds a real unresolved conflict.

### Output
`TYPOGRAPHY_LOCK_CANDIDATE`

## P2 — Iconography / Sign Grammar Lab

**Execution status: HUMAN APPROVED / CLOSED (2026-09-22).**

The human owner selected **I-C — Minimal / No-Icons**.

Attempt 01 remains quarantined as negative evidence. The later Figma S1/S2/S3 surrogate remains non-canonical technical scratch.

The approved rule is not “never use any mark.” It is:
- no decorative icon system by default;
- use signs only when they carry real content-specific function;
- morphology remains embodied in the visual matter;
- typography, composition and matter carry most identity load;
- fake coordinates, arbitrary scales, meaningless crosshairs/tick marks, invented scientific metadata and decorative lines without semantic targets are prohibited as AI slop.

Lock document:
`docs/03-brand/workbench/divinivid/generation/P2_SIGN_GRAMMAR_LOCK_MINIMAL_V1.md`.

### Objective
Determine whether DIVINIVID needs a formal icon system at all, and if so, define only the minimum native grammar.

### Hypotheses

#### I-A — Measurement
- coordinates;
- crosshairs;
- cut marks;
- scale;
- origin;
- index;
- registration.

#### I-B — Morphological Notation
Abstract notation for:
- cavity;
- layer;
- transition;
- continuity;
- pressure;
- rupture;
- revelation.

Not literal pictograms.

#### I-C — No-Icons / Minimal Signs
Rely primarily on:
- numerals;
- lines;
- coordinates;
- typography;
- functional geometry.

### Hard fails
Reject:
- occult/alchemical shorthand;
- runes;
- arbitrary sigils;
- sci-fi icon packs;
- decorative Japanese symbols;
- ornamental glyph families with no operational meaning.

### Budget
- initial three-hypothesis sheet: consumed and rejected;
- targeted repair: consumed and human-approved as I-C Minimal / No-Icons;
- P2 budget closed.

### Output
`SIGN_GRAMMAR_LOCK_CANDIDATE`


## Tool-use discipline before final expression lock

Figma is a precision/behavior tool, not the default engine for unresolved aesthetic invention.

Use Figma before final lock only when the active question materially requires:
- deterministic composition;
- responsive validation;
- component/state behavior;
- motion implementation.

Do not use Figma by default to:
- invent unresolved iconography;
- replace an approved visual anchor with a surrogate reconstruction;
- substitute an approved typographic direction with a proxy font;
- create design-system artifacts before the corresponding visual decision exists.

Full Figma Production System remains downstream of `DIVINIVID_FINAL_EXPRESSION_LOCK_V1`.

## P5 — Motion Lab

### Objective
Define the native motion grammar.

### Motion families

#### M-A — Breathing Matter
Slow expansion/contraction/pressure.

#### M-B — Registration
Printed layers separate, misregister and re-align.

#### M-C — Negative Revelation
Meaning appears because another layer erodes, masks, withdraws or exposes absence.

#### M-D — Instrument Response
Minimal coordinate/index/measurement reaction.

### Rules
Motion must:
- reveal;
- measure;
- transform;
- relate.

Motion must not exist merely to decorate.

### Budget
- four short 3–6 second studies;
- maximum one targeted repair per study when a concrete failure is identified.

### Output
`MOTION_GRAMMAR_LOCK_CANDIDATE`

## P7 — Application Stress Test

### Objective
Prove the identity outside its ideal presentation.

### Contexts
1. Agency website;
2. Proposal / sales deck;
3. Case study / editorial;
4. Social / campaign;
5. Clinical / B2B-sensitive context.

### Stress condition
At least one context must restrict a familiar identity crutch, e.g.:
- minimal crimson;
- very high information density;
- light/ivory field;
- minimal imagery.

The identity must survive without relying on:
`black + crimson + texture = DIVINIVID`.

### Budget
- one evidence surface per context;
- one contextual repair only where a material failure exists.

### Output
`APPLICATION_STRESS_REPORT`

## P8 — Final Pre-Lock Synthesis

### Objective
Synthesize accepted module decisions without inventing a new aesthetic.

### Inputs
Only human-approved outputs from P1–P7.

### Required output
`DIVINIVID_FINAL_EXPRESSION_SPEC_V1`

It must define:
- Core DNA reference;
- principal expression base;
- morphology;
- typography;
- sign grammar;
- color semantics;
- intensity scale;
- motion grammar;
- digital behavior;
- application rules;
- bestiary boundary;
- Anti-Canon updates.

Then produce one single final synthesis artifact demonstrating coexistence of the approved rules.

### Final audit gates

#### G1 — Identity Integrity
All modules belong to one universe.

#### G2 — Elasticity
Identity survives D1–D4.

#### G3 — Commercial Viability
The system can sell services and generate trust.

#### G4 — Production Viability
The identity can become Figma/code without requiring unique raster artwork for every interface state.

### Outcomes
- `PASS`
- `TARGETED_FIX`
- `FOUNDATIONAL_FAILURE`

A foundational failure is the only outcome that can justify reopening B1/Core, and still requires explicit human approval.
