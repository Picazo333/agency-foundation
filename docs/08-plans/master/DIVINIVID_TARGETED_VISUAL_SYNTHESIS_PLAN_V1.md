# DIVINIVID Targeted Visual Synthesis Plan V1

## Purpose
Replace open-ended / quota-driven moodboard execution with a small number of high-value, human-gated visual pieces that resolve actual production questions.

The historical 100-contract corpus remains useful as a coverage/reference checklist. It is no longer a requirement to render 100 moodboards.

## Governing principle
Quality and simplicity first. Complexity enters only when it resolves an identified risk or unlocks a required capability.

## Current locked hierarchy

```
DIVINIVID_CORE_LOCK_V1
```

## Phase M1 — Morphological development

### Objective
Make B1 capable of expressing structures that can be read simultaneously across multiple scales and domains without becoming literal illustration.

Target reading families:
- anatomy / marrow / membrane;
- planetary / celestial mass;
- geology / relief;
- coast / sea / delta;
- mountain / landscape;
- organism / specimen;
- architecture / cavity.

### M1-A — Anatomía Celeste
Primary emphasis:
- marrow;
- cavity;
- membrane;
- bone;
- living tissue;
- microstructure.

Secondary reading:
- planet;
- moon;
- orbit;
- suspended mass;
- celestial body.

### M1-B — Topografía Orgánica
Primary emphasis:
- coast;
- plate;
- sea;
- fissure;
- mountain;
- delta;
- relief.

Secondary reading:
- organ;
- tissue;
- marrow;
- internal anatomy;
- biological membrane.

### M1 acceptance
Each candidate should pass:
1. ambiguity — meaningful multiple readings;
2. non-literality — not medical illustration or literal cartography;
3. continuity — recognizably B1;
4. depth — added semantic richness, not cosmetic detail;
5. elegance — no uncontrolled visual excess;
6. applicability — usable in editorial/web/system contexts;
7. low cliché risk.

### M1 gate
Human decision:
- select M1-A;
- select M1-B;
- or authorize one bounded synthesis using only the strongest proven contribution from each.

No automatic synthesis.

## Phase M2 — Elegant Brutalist Elevation

### Preconditions
M1 human gate passed.

### Objective
Increase professional severity, architectural clarity and elegance without destroying dream depth or living matter.

### Brutalism may affect
- hierarchy;
- grid discipline;
- structural cuts;
- typographic presence;
- spacing;
- contrast;
- architecture of information;
- compositional decisiveness.

### Brutalism may not erase
- ambiguous matter;
- oneiric depth;
- negative-shape logic;
- printed-evidence behavior;
- macro/micro duality;
- Core palette semantics.

### M2-Soft
A restrained increase in:
- precision;
- spacing discipline;
- typographic confidence;
- architectural order.

### M2-Hard
A stronger but still elegant increase in:
- structural mass;
- severe hierarchy;
- hard spatial decisions;
- monumental editorial presence.

### M2 acceptance
1. Core preserved;
2. M1 morphology preserved;
3. elegance increases;
4. structural clarity increases;
5. no generic brutalist rebrand;
6. matter remains alive;
7. translation to agency/web becomes easier.

### M2 gate
Human comparison selects the base for:
`MAIN_SYSTEM_B2`.

## Bestiary branch
`BESTIARY_BASE_B0` remains dormant during M1/M2.

It will be developed only after the principal B1 evolution is resolved.

Its future scope:
- entity taxonomy;
- apparition behavior;
- bestiary applications;
- campaign / hero signature imagery.

## Iteration budgets
To control token and generation waste:

| Operation | Default budget |
|---|---:|
| M1-A full candidate | 1 |
| M1-B full candidate | 1 |
| M1 synthesis | 0 unless human-authorized |
| M2-Soft full candidate | 1 |
| M2-Hard full candidate | 1 |
| full regeneration of an accepted direction | prohibited by default |
| targeted repair | 1 when a concrete defect exists |

## Minimum-necessary-mutation rule
Each candidate must preserve the previous approved base and change only the named development dimension.

A candidate that improves one axis by silently redesigning unrelated parts fails the contract.

## No premature downstream work
Before M1/M2 completion, do not:
- industrialize the full Figma design system;
- start v0 production;
- redesign the website;
- develop the bestiary branch;
- reopen the Core.

## After MAIN_SYSTEM_B2
The expected next macro sequence is:

```
MAIN_SYSTEM_B2

  -> identity synthesis / lock
  -> Figma production system
  -> website strategy + IA
  -> Golden Slice
  -> technical feasibility spike
  -> full Figma prototype
  -> v0/code prototype

  -> brandbook readiness handoff
```

This later sequence remains subject to its own approved execution plan and does not authorize work merely by appearing here.
