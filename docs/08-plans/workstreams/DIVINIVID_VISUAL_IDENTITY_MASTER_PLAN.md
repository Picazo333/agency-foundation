# DIVINIVID Visual Identity Master Plan

## 0. Freeze declaration

This document is the approved execution contract for the DIVINIVID visual-identity program.

It was approved by the human creative owner on 2026-09-16 after an explicit planning sequence consisting of:
- 20 iterative planning passes;
- 10 red-team passes;
- 10 correction passes;
- 10 polish passes;
- 10 execution-detail passes;
- reconciliation against the repository's Brand, capability-governance and Asset Factory contracts.

The purpose of the freeze is not to prevent learning. It prevents **silent process drift**. Any material change to phase order, gate semantics, Brand/route hierarchy, source-of-truth rules, or the invariants below requires a documented `PLAN_DEVIATION` with reason, evidence, impact and explicit human approval.

This plan governs method. It does **not** pre-approve any visual artifact, typeface, exact color, logo, asset, or final Brand Direction.

---

# 1. Brand hierarchy and thesis

## 1.1 Naming hierarchy

- **DIVINIVID** — working selected Brand name for identity exploration.
- **KIROGRAF** — internal codename for Route 01 only; never substitute it for the Brand in public-facing applications.
- **Sacred Anatomy** — internal descriptor for KIROGRAF.

Naming remains subject to final legal/trademark/domain diligence. Visual selection is not legal clearance.

## 1.2 Central thesis

> **DIVINIVID contrasts with elegance the tension and harmony between the divine and the grotesque, darkness and light, demonstrating how apparent opposites can coexist inside one system.**

## 1.3 Five master tensions

1. `DIVINE ↔ GROTESQUE`
2. `LIGHT ↔ DARKNESS`
3. `ORDER ↔ ABERRATION`
4. `KNOWLEDGE ↔ MYSTERY`
5. `BODY ↔ TRANSCENDENCE`

The identity does not succeed by choosing one pole. It succeeds when the relationship between poles is legible, intentional and coherent.

# 2. Non-negotiable operating invariants

1. **DIVINIVID is the Brand.** Route names are internal metadata.
2. Recent failed moodboard/generation rounds are `NON_CANONICAL / NEGATIVE_EVIDENCE`; they cannot seed later generations.
3. A generated artifact may influence a later phase only after explicit human approval.
4. Historical/cinematic/art references are translated into principles before production; whole-style imitation is prohibited.
5. **Figma is the editable visual source of truth** once visual artifacts begin to be assembled. Image generators create ingredients, not complete identities.
6. Generative systems may produce visual matter; they do not decide canon.
7. No tool, model, skill or agent approves its own output.
8. Divergent design phases use the **5-Up Rule**: five meaningfully different hypotheses when five-way divergence is called for; cosmetic variants do not count.
9. Convergent phases do not manufacture five outputs merely to satisfy a number.
10. Every material creative gate resolves to `PASS`, `MUTATE`, or `KILL`.
11. A gate may not be skipped because generation is expensive or a result is visually appealing.
12. The grid is infrastructure, not a mandatory visual aesthetic.
13. Brand V0 remains provisional until Brand/Business Fit Review.
14. Asset Factory production remains blocked until Brand V1 supplies a validated Brand Pack.
15. Source provenance and rights state travel with reference and production assets.
16. Capability methods remain subordinate to repository governance, this frozen plan, active route contracts and human creative authority.

# 3. Clean source doctrine

## 3.1 Reference precedence

When references conflict, use this precedence:

1. direct human approvals/rejections recorded in the Brand workbench;
2. approved/frozen Brand process contracts;
3. source works and source-specific extraction notes;
4. route hypotheses approved at a gate;
5. approved generated artifacts;
6. non-canonical experiments only as negative evidence.

## 3.2 Contamination rule

Never use a previous generated board as a visual reference simply because it exists. For every future visual output, the operator must be able to identify the **real source references or approved grammar rules** that justify it.

## 3.3 Reference record schema

Every reference admitted to the active Atlas records:

- `SOURCE`
- `DATE / CONTEXT`
- `WHY IT MATTERS`
- `EXTRACT`
- `DO NOT EXTRACT`
- `MASTER TENSION(S)`
- `INSPIRATION / EXECUTION`
- `PROVENANCE / RIGHTS STATE`
- `HUMAN STATUS: CANDIDATE / APPROVED / REJECTED`

# 5. Execution topology

## 5.1 Serial convergence bottlenecks

The following must complete in order and require human convergence before dependent work proceeds:

`Creative Direction Contract → Reference Atlas → Tension Grammar → Route Territory Selection → Signature Selection → Foundations Freeze → Brand Direction Selection`

## 5.2 Safe parallelization

The following may run concurrently after their upstream contract exists:

- the nine Reference Research lanes;
- provenance/rights research;
- asset-family generation inside a single approved route grammar;
- independent QA/red-team passes;
- application variants after the relevant identity layer is frozen.

Parallel work must not create competing sources of truth.

# 6. Phase protocol

Every phase uses the same operational envelope:

1. **READ** — frozen plan + current Brand State + active route contract + required skill adapters.
2. **PREFLIGHT** — capability check; do not install speculative tooling.
3. **DECLARE** — objective, inputs, output path, variables being tested, invariants and stop condition.
4. **DIVERGE** — only where phase calls for divergence.
5. **CURATE** — cut weak/redundant work; record rejections.
6. **RED TEAM** — test genericity, drift, contamination, system weakness and application failure.
7. **GATE** — `PASS / MUTATE / KILL` with evidence.
8. **RECORD** — write decision/rejection and provenance; no silent promotion.
9. **HARVEST** — capture reusable process learning only when meaningful under Project Harvest.

# 10. Phase 3 — Reference Atlas

## Objective
Build five tightly argued source-only boards. No AI-generated project art is permitted as a source board reference.

## Five boards
1. `DIVINE / ILLUMINATION`
2. `GROTESQUE / CORPOREAL`
3. `DARKNESS / REVELATION`
4. `ORDER / KNOWLEDGE`
5. `RECONCILIATION`

The fifth board is the critical board: works where apparently opposed qualities already coexist successfully.

## Board contract
- 8–16 surviving references after broader sourcing;
- dimensions visibly covered: color/tone, material/texture, light/shadow, composition/space, human/body presence where relevant;
- every reference labelled `INSPIRATION` or `EXECUTION`;
- source/extract/do-not-extract notes available;
- separate Anti-Atlas.

## Tooling
Figma assembles the boards. Moodboard Builder and Visual Asset Curation govern curation.

## Gate
With names/authors hidden, a reviewer should still describe a direction close to the Creative Direction Contract.

# 11. Phase 4 — Tension Grammar

## Objective
Stop designing from artists and start designing from rules.

## Grammar domains
- light;
- color;
- body;
- grotesque;
- geometry;
- composition;
- texture/material;
- annotation/information;
- symbolism;
- motion;
- narrative;
- density.

## Translation pattern
`SOURCE → OBSERVED MECHANISM → ABSTRACT RULE → ALLOWED USE → MISUSE / LIMIT`

Example form only: a source may yield `dominant darkness + localized semantic illumination`, not “make it look like [artist]”.

## Output
`DIVINIVID_VISUAL_GRAMMAR_V0.md`

## Gate
A capable designer unfamiliar with the source artists can use the grammar to make a relevant artifact without copying a reference.

# 12. Phase 5 — KIROGRAF Territory 5-Up

## Objective
Test five distinct mechanisms for resolving the same DIVINIVID thesis inside Route 01.

## Hypotheses
A. **Illumination Invades Anatomy** — rational monochrome structure invaded by sacred pigment.

B. **Grotesque Inside Order** — disciplined system deliberately contains anomaly.

C. **Light Reveals the Uncomfortable** — illumination confers significance on what would normally be hidden.

D. **Sacred Marginalia** — central order; strange living matter occupies margins.

E. **Celestial / Corporeal Mirror** — body and cosmos share structural geometry.

## Each 5-Up must state
- `HYPOTHESIS`
- `VARIABLE BEING TESTED`
- `WHAT REMAINS CONSTANT`
- `SOURCE PRINCIPLES USED`
- `WHAT THIS TEACHES`
- `KNOWN FAILURE RISK`

## Gate
Select/mutate based on mechanism fertility, distinctiveness and system potential — not prettiness alone.

# 15. Phase 8 — Foundations

## Objective
Convert selected signature/territory into functional foundations.

### Typography
Roles first; candidate fonts second. Validate ES/EN coverage, readability, weight/style range, web/print delivery and licensing. A maximum of two type families is the default; exceptions require rationale. Custom wordmark logic is independent from body/display font selection.

### Color
Start from historical territories — ink/ivory, ultramar, carmine/vermilion, aged gold — but do not assume final hex values. Define roles, tonal behavior, accent budgets, neutrals, semantic mappings and light/dark surfaces as required.

### Accessibility
Measure real pairings. Decorative pigment is not automatically text color. Do not claim compliance from swatches.

### Other foundations
Spacing, line/stroke behavior, borders/frames, texture budget, annotation hierarchy and foundational tokens where evidence supports them.

## Gate
The system remains recognizable and usable with imagery removed.

# 28. Transversal quality protocol

Every material artifact or set is checked against eight gates:

| Gate | Question |
|---|---|
| Intent | Does it answer the active brief/thesis? |
| Duality | Are the relevant poles actually co-present/reconciled? |
| Reference | Are principles extracted rather than styles copied? |
| Distinctiveness | Could this belong to any agency/template? |
| Systemness | Can another designer reproduce it from rules? |
| Application | Does it work outside the hero/mockup? |
| Contamination | Did failed/generated precedent leak back in? |
| Craft | Is the execution worth preserving? |

A `PASS` requires no critical failure. `MUTATE` names specific corrections and keeps the same hypothesis. `KILL` retires the hypothesis and records why.

Taste challenges genericity/drift; Impeccable refines where appropriate; specialist methods validate their layer; the human creative owner approves convergence.

---

# 29. Negative-evidence protocol

A failed experiment is not deleted from project memory if it teaches a durable boundary. Record:
- artifact/round identifier;
- intended hypothesis;
- failure mode;
- anti-pattern extracted;
- whether any sub-element survives;
- `DO NOT SEED FUTURE GENERATION` flag where applicable.

Do not preserve every weak output. Low-signal failures can be discarded under Project Harvest rules.
