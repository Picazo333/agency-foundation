# DIVINIVID Execution Error Ledger V1

## Purpose

Maintain a concise, durable record of high-signal execution failures so the project does not relearn the same lesson through repeated cost.

This is not an archive of every weak generation. Only errors that change process, tooling or quality criteria belong here.

## E-01 — Canon cursor / contractual lineage mismatch

**Observed**
Historically approved visual boards were initially treated as if they occupied contractual A11-A15 slots even though their lineage did not match the Plan Lock contracts.

**Impact**
Visual approval and contractual completion were conflated.

**Correction**
Reclassify the five visually approved boards as `STYLE-S01-S05` execution-style anchors while preserving the true contractual cursor separately.

**Portable rule**
Visual quality does not repair lineage. Artifact identity and approval status are independent dimensions.

---

## E-02 — Reference authority drift

**Observed**
Later generations were visually competent but drifted toward older ivory/editorial states because semantic Canon and latest execution-style references were mixed.

**Impact**
Recency and broad canon silently overrode the current surface authority.

**Correction**
Separate:
- semantic Canon;
- execution-style anchors;
- negative/quarantined evidence.

**Portable rule**
Positive context needs typed authority.

---

## E-03 — Reference availability mistaken for active conditioning

**Observed**
Approved reference files were retrievable and inspectable, but the runtime could not prove that their pixels were attached/effective in the generation request.

**Impact**
Repeated outputs fell into stable generic priors despite correct repo state.

**Correction**
`REFERENCE_AVAILABLE != REFERENCE_BOUND != REFERENCE_EFFECTIVE`.

Use reference-binding attestation and stop if executor support cannot be verified.

---

## E-04 — Monolithic generation overloaded with deterministic requirements

**Observed**
A single image-generation call was asked to solve art direction, exact text, diagrams, information architecture and composition.

**Impact**
Outputs drifted toward generic infographic/dashboard or gothic-premium conventions.

**Correction**
Use generative models for bounded visual matter and deterministic assembly for exact typography/diagram/layout when required.

---

## E-05 — Ungated executor substitution

**Observed**
Runway was called for A12-A15 during a recovery path without proving equivalence to the intended image executor.

**Impact**
Continuity and reference-conditioning assumptions broke.

**Correction**
Executor substitution requires a compatibility gate.

---

## E-06 — P2 Figma surrogate altered variables outside scope

**Observed**
A Figma sign-grammar test used simplified surrogate morphology and proxy typography.

**Impact**
The experiment changed more than sign grammar, invalidating the comparison.

**Correction**
Quarantine the surrogate. Enforce one-variable testing and source-asset fidelity.

---

## E-07 — AI-slop instrumentation

**Observed**
Generic coordinates, meaningless lines, fake scientific marks and arbitrary technical decoration appeared in sign/icon tests.

**Impact**
DIVINIVID gained simulated meaning instead of actual information.

**Correction**
P2 Minimal / No-Icons. Signs are allowed only when they carry real content-specific function.

---

## E-08 — Hero comparison contaminated by visual redesign

**Observed**
An early P3 comparison changed morphology, compositional language and typography instead of only changing hero behavior.

**Impact**
H-A/H-B/H-C could not be compared cleanly.

**Correction**
Repair with M1-B + P1 + P2 fixed and vary only art/message/proof/CTA relationship.

---

## E-09 — Figma invoked before it had a deterministic job

**Observed**
Figma calls were used for exploratory/surrogate work that image generation or direct reasoning handled better.

**Impact**
Complexity increased without proportional quality gain.

**Correction**
Figma is allowed before Final Expression Lock only for a declared deterministic need.

---

## E-10 — Low-resolution proxy enlarged as if production asset

**Observed**
A roughly thumbnail-scale raster proxy was enlarged into a major P6 identity field.

**Impact**
Blur reduced visual fidelity and undermined the test.

**Correction**
Asset-resolution suitability becomes a Figma call DoD requirement.

---

## E-11 — Static Figma surface mislabeled as Digital Behavior evidence

**Observed**
P6 built two static compositions but did not meaningfully test responsive behavior, interaction states or approved motion grammar.

**Impact**
The artifact answered a weaker question than the gate required.

**Correction**
Reclassify as Structural Probe V0. Future P6 must test identity behavior, not merely static layout.

---

## E-12 — Premature product/UI semantics before identity completion

**Observed**
P6 introduced interface structure while signature, production typography, foundations, composition grammar and image language were not fully formalized.

**Impact**
The project began solving downstream web/product questions with unresolved upstream identity inputs.

**Correction**
Insert R0-R5 identity formalization before P6.

---

## E-13 — State-file inconsistency

**Observed**
`CURRENT_GENERATION_STATE.yaml` duplicated `P5_MOTION` in sequence and did not fully reflect all closed modules in the completed list.

**Impact**
The repo could reconstruct an ambiguous cursor even though the conversation state was clearer.

**Correction**
State files must be audited whenever a gate is closed or sequencing changes.

# What has worked well

The project has also produced several strong process improvements:

- repository-first authority;
- human-gated visual promotion;
- quarantine instead of silent deletion/reuse;
- Core/B1/B0 separation;
- minimum-necessary mutation;
- M1-B as a bounded working anchor rather than accidental canon;
- P2 anti-slop rule;
- P3 targeted repair instead of accepting a contaminated comparison;
- P4 order/creativity tension and structural variety;
- P5 role-separated motion grammar;
- willingness to stop quota-driven 100-board rendering when marginal value declined;
- explicit postmortems and Project Harvest.

# Operating rule

When an error produces a durable rule, update:
1. the relevant execution contract;
2. current state if the cursor changed;
3. Project Harvest if the lesson is portable.

Do not create a new governance layer for a one-off cosmetic mistake.
